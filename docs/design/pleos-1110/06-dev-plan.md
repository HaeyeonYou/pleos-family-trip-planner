# 11/10 확정 디자인 개발 플랜

작성: 2026-11-10. 근거 문서: `04-dev-spec-and-code-gap.md`(코드와의 차이), `03-flow-components-states.md`(흐름·상태), `05-gaps-and-open-questions.md`(질문 Q01~Q40), `01-inventory-and-tokens.md`·`tokens.json`(값).
크기 표기: S 반나절 이내 / M 1~2일 / L 3일 이상 (모두 추정). 이 문서의 일정과 순서는 **제안**이고, 결정이 필요한 것은 "결정 대기"로 표시했다. 메인 체크아웃의 `docs/development-plan-1110.md`(다른 에이전트가 쓴 분석)와는 18곳이 다르며, 값이 겹치면 이 문서 묶음(Figma 대조 완료)을 따른다 (`04` 5절).

## 0. 한 장 요약

- 11/10 안은 색·메뉴·입력·레이아웃이 모두 옛 디자인(초록 HF 01~06)과 다르다. **화면 하나만 바꾸는 일이 아니라 앱 셸 교체**다. 그래서 공통 기반(P0)을 먼저 하지 않으면 화면마다 두 번 일하게 된다.
- 앱이 그리는 것은 `App · 시터노트` 1256x886 프레임뿐이다 (차량 패널·상태바·독은 Pleos OS).
- 서버는 대부분 이미 있다 (재계산 `/course/schedule`, 모드 동기화 `/presets`, 급한 케어 `/care/nearby`, 다중 아이 `/me/children`). **없는 것**: 소아과·약국, 휴게소·졸음쉼터, 단골 케어 장소(방문 기록으로 앱에서 계산 가능), 모드 적용 시점, 반경 선택.
- 가장 큰 앱 작업: 공통 셸·토큰, 케어 3열 + 상황 슬롯, 다중 아이 상태 모델, 홈 3열.
- 막힘이 되는 결정 5개: 그로우 최종안(Q32), 슬롯 우선순위(Q03), "수유 중" 상태(Q06), 아이별 상태 범위(Q12), 소아과·약국 칩(Q15). 6절.

## 4. 브랜치·이슈 단위 제안

프로젝트 규칙(`docs/HANDOFF.md` 0절)에 따라 이슈 하나당 `feature/<번호>-<이름>` 브랜치 하나, PR로 바로 병합. 한 PR은 하나의 화면 또는 하나의 공통 컴포넌트 묶음으로 작게 유지한다.

1. `토큰·타이포` (P0-1·P0-2) — 단독, 가장 먼저
2. `공통 컴포넌트` (P0-3), `아이콘 이전` (P0-6) — 병렬 가능
3. `셸 교체` (P0-4·P0-5·P0-7) — 1·2 이후
4. 이후 화면 단위 이슈: 케어 그리드, 수유 타이머, 급한 케어, 경유지 완료, 모드 편집, 아이 선택, 수면, D01, 홈, 코스 상세, 대체 장소
5. 서버 S1·S2·S4·S5는 앱과 파일이 겹치지 않아 병렬 세션 가능 (서버 테스트 `cd server && .venv/bin/pytest -q`)

같은 파일을 두 세션이 동시에 고치지 않게 한다 (`Theme.kt`, `AppShell.kt`, `CareScreen.kt`, `MainActivity.kt`가 충돌 지점).

## 5. 검증 방법

- 단위: `cd android && ./gradlew :app:testDebugUnitTest` (JDK 17). 순수 함수(슬롯 우선순위, 수유 타이머 상태, 자주 가는 장소, 지연 문구)는 테스트를 같이 쓴다.
- 화면: 에뮬레이터 캡처를 Figma 화면(`assets/screens/*.png`)과 나란히 놓은 비교 이미지를 `docs/screenshots/`에 둔다. 공유 에뮬레이터라 앱 ID 접미사(`-PappIdSuffix=.xxx`)로 분리하고 설치 시각을 확인한다.
- 주행·정차: 에뮬레이터 Virtual Console의 기어 값과 `tools/geo_drive.py` 주행 시뮬레이션. 주차 브레이크·차속·시스템 야간 테마 신호는 SDK로 읽히는지 먼저 검증 (Q01).
- 확인하지 못하는 것(실차, 실제 앱 창 크기)은 PR 본문에 그대로 적는다.

## 7. 다른 세션이 이 문서를 쓰는 법

1. 먼저 `README.md`(이 폴더)를 읽는다. 화면 번호와 노드 id는 `02`, 값은 `tokens.json`, 이미지는 `assets/`.
2. 맡은 작업의 행(P?-?)과 그 화면의 `04` 2절·`05` 1절을 읽는다.
3. Figma 호출이 필요하면 읽기 전용으로, 호출 수를 아껴서 쓴다 (병렬 스크린샷이 한도에 걸렸다. `README.md` 참고).
4. 결정 대기 항목을 건드리는 작업이면 사용자에게 한 번에 하나씩 묻는다.
