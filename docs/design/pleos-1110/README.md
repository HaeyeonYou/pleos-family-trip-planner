## 핵심 사실 8가지

1. 앱이 그리는 것은 `App · 시터노트` 프레임 **1256x886**(위치 652,76)뿐이다. 차량 패널·상태바·독은 Pleos OS 몫이다. 현재 앱의 창 규칙(1682x1210dp)과 다르므로 실측이 먼저다 (`06` P0-0).
2. 주색이 초록(#0E8A5F)에서 인디고(#4D55F0)와 그라디언트(#1F80FF→#5B4BF5→#8A1EE6)로 바뀐다. 왼쪽 140dp 메뉴 레일은 사라지고 홈·케어·그로우·설정 바로가기가 3열째 아래 카드(392x92)로 간다. 마이크는 상단 음성 입력줄 안으로 간다.
3. 모든 화면이 **3열 그리드**(여백 24, 열 392, 간격 16)다. 케어는 오른쪽 아래 한 칸(392x370)이 상황에 따라 바뀌는 슬롯이고, 겹칠 때의 우선순위는 디자인에 없다 (결정 대기).
4. 글꼴은 목표가 Pretendard이고 파일의 실제 글꼴은 Asta Sans다 (노트 357:1735). 10단 스케일(Display 56 … Caption 15)이 있다.
5. 셸 변형은 3개뿐이다 (Light/정차, Dark/정차, Light/주행). 다크는 C04 한 화면, 주행은 D01 한 화면에서만 쓰였다.
6. 프로토타입 연결(`reactions`)이 디자인에 **없다**. 화면 이동은 디자이너 노트·글·구조로 추정한 것이다 (`03`).
7. 서버는 대부분 있다. 없는 것: 소아과·약국, 휴게소·졸음쉼터, 모드 적용 시점, 반경 선택. 새 API를 만들 필요가 없는 것: 코스 재계산(`/course/schedule`), 모드 동기화(`/presets`), 급한 케어(`/care/nearby`).
8. 기획 코드 K3~K14의 정의는 레포 `docs/`에 없고, 같은 Figma 페이지의 `11/9일_케어 디벨롭 ver`(343:11731) 섹션에 있다 (`05` 4절).

## 한계 (읽기 전에 알아 둘 것)

- 앱 실제 창 크기, 시스템 야간 테마·주차 브레이크·차속 신호, 휴게소·졸음쉼터 공공데이터 서비스는 확인하지 못했다.

- 화면 속 숫자·장소 이름은 샘플이다 (같은 장소의 거리가 화면마다 다름).
- mermaid 그림(`03`)은 렌더링해서 확인하지 못했다.
- 아이콘 등장 화면과 용도 일부는 추정이다.

## 작업 방식 기록

- Figma는 읽기 전용(`get_screenshot`, `use_figma` 조회)으로만 썼다. 어떤 노드도 만들거나 바꾸지 않았다.
- **Figma MCP 호출 한도(Education 플랜)**: 서브에이전트가 스크린샷을 병렬로 요청하자 한도에 걸려 일부가 실패했다. 한 장씩 순서대로 받으면 통과했다. 정확한 호출 수와 초기화 주기는 확인하지 못했다. 앞으로 이 자료를 더 받을 때는 호출을 줄이고 순서대로 요청한다.
- 서브에이전트: Haiku 3개(인벤토리·토큰, 화면 요약, 에셋 저장), Sonnet 3개(흐름·상태, 명세·코드 차이, 누락·질문), Haiku 1개(아이콘 재저장). 메인 세션이 결과를 읽고 사실과 어긋난 곳(C04 다크 범위 등)을 고쳤다.
