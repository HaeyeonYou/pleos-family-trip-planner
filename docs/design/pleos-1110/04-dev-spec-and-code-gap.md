### 1.2 앱 영역 크기: 현재 규칙과의 차이

| | 현재 앱 | Figma |
|---|---|---|
| 창 크기 | 1682x1210dp (`A/ui/Common.kt:43` 주석, 프로젝트 결정) | 앱 프레임 1256x886 (352:2747) |
| 가로세로 비율 | 1.390 | 1.418 |
| 좁은 창 규칙 | `screenWidthDp < 1200`이면 세로 창으로 보고 한 줄 쌓기 (`Common.kt:44,51`, 화면 7곳이 사용: CareScreen:69, HomeScreen:85, CourseScreen:101, CourseOverview:61, ExperienceScreen:105, SettingsScreen:89, InputScreen/ProfileScreen) | 좁은 창 디자인은 없음. 1256은 1200보다 겨우 56 큼 |

- 1 Figma px = 1dp 규칙을 그대로 쓰면 앱은 1256dp 폭으로 설계된다. 실제 창이 1682dp라면 같은 레이아웃은 배율 약 1.34(폭 기준)로 키워야 같아 보이고, 높이는 886*1.34 = 1186으로 1210에 24dp 남는다(계산값).
- 선택지 (결정 필요, 미확인): (A) 1256x886 디자인 캔버스를 만들고 `LocalDensity`를 곱해 균일 확대(가장 Figma와 같음, 권장). (B) 각 화면을 `weight`로 늘려 1682 폭에 퍼지게 함(Figma와 모양이 달라짐). (C) 실제 Pleos 앱 노출 영역이 이미 1256x886dp 근처라면 현재 규칙 그대로. **실제 단말에서 앱이 받는 창 크기와 밀도는 이번 조사로 확인하지 못했다.** 먼저 에뮬레이터/실차에서 `screenWidthDp`를 찍어 봐야 한다.
- 좁은 창(분할 화면)은 디자인이 없으므로 기존 세로 쌓기 폴백을 유지할지 별도 결정이 필요하다. (A)를 쓰면 배율 때문에 `screenWidthDp`가 항상 디자인 폭이 되어 `isNarrowWindow()`가 영원히 false가 되므로, 판정은 확대 전 실제 폭으로 해야 한다.
- 근거 코드: 현재 레이아웃은 화면마다 `padding(start = 56.dp, …)`(HomeScreen.kt:113), `padding(horizontal = 40.dp)`(CareScreen.kt:73) 등 서로 다른 여백을 쓴다. Figma는 전 화면 공통 바깥 여백 24 · 열 392 · 간격 16이므로 공통 래퍼로 통일해야 한다.

## 6. 확인하지 못한 것과 추정, 이상한 점

확인하지 못한 것
- 실제 Pleos 단말이 앱에 주는 창 크기·밀도(1.2절). 1682x1210dp는 프로젝트 결정값이고, Figma 1256x886과의 관계는 문서로 확인하지 못했다.
- Figma에서 읽은 범위: 구조·좌표·색·글자는 화면 최상위 자식과 컴포넌트 라이브러리, H01·C01 앱 프레임 전체, C03~C06 프로액티브 카드 상세, D01 모달 상세에서 읽었다. H02 타임라인 행 내부, G01 그래프 노드 상세, C07~C11 시트 안쪽 행의 좌표·색은 스크린샷으로만 확인했다(글자·구성은 확인, 정확한 치수는 미확인). `get_design_context`(코드·에셋 추출)는 쓰지 않았다.
- 설정 탭: 11/10 섹션에 설정 화면 디자인이 없다. 바로가기의 "설정"이 연결될 화면 규격은 미확인(현재 `SettingsScreen`을 새 토큰으로만 입히는 것으로 추정).
- 좁은 창(분할 화면)용 디자인 없음.
- Pretendard 글꼴 파일 번들 여부와 라이선스.
- 시스템 야간 테마 신호, 주차 브레이크, 실제 차속을 Pleos가 앱에 주는지(1.6절).
- 휴게소·졸음쉼터 데이터 소스의 존재와 형식(4절).
- "K3~K14" 번호의 출처: 노트에 `K3 수면 모드`, `K4 정차`, `K5 임박/지남`, `K6 경유지 추가 완료`, `K7 수유실 후보`, `K7-2 정차 공간`, `K8 결과 없음`, `K13 첫 기록 전`, `K14 아이 선택`, `HF03-1 모드 편집`으로 나온다. 기획 쪽 기능 번호로 추정되며 저장소 문서에서는 찾지 못했다(`docs/` 검색 없음).

추정
- 상태바의 "운"은 차량(OS)이 그리는 사용자 표시이고 앱 소관이 아니다. 앱 안의 "서"는 아이 아바타다.
- H02의 날씨 "서울 중구"는 현재 위치가 아니라 코스 장소 기준으로 보인다.
