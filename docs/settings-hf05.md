# 차 앱 설정(HF05)과 선호 조건 (이슈 #128)

Figma 지수 페이지 `HF 05 설정`(노드 `210:1031`)을 차 앱에 옮긴 내용과, 화면 값이 실제로 어디에 저장되고 무엇에 쓰이는지를 적는다.

## 화면 구성 (`ui/SettingsScreen.kt`)
안내 줄 → 제목 → 카드 4개(2×2, 좁은 창에서는 한 줄씩) → 계정·개발자 줄.

| 카드 | 내용 | 값이 있는 곳 |
|---|---|---|
| 가족 프로필 | 아이별 출생 연월·생후 개월, 반려동물, '가족 정보 수정' 버튼(가족 정보 화면으로) | `ProfileStore` (기존) |
| 루틴 | 수유 간격 −/+ (30분 단위, 60~360분), 낮잠 시간(누르면 시작·끝을 30분씩 조절) | 수유 간격: `FeedingStore` (케어 화면·홈 수유 카드와 **같은 값**), 낮잠: `SettingsStore` |
| 선호 조건 | 토글 4개 | `SettingsStore` |
| 개인정보·데이터 | 저장 위치·서버 전송 안내, '데이터 전체 삭제' | — |

로그인 상태·로그아웃·개발자 화면 진입은 카드 아래 한 줄로 그대로 둔다.

### 주행 중
버튼·토글은 주행 중에도 쓸 수 있고(조수석 조작), 키보드 입력이 필요한 가족 정보 수정은 그 화면에서 정차 중에만 가능하다(기존 규칙). 이 화면에는 키보드 입력이 없다. Figma 안내 줄 문구('주행 중에는 보기만 가능')는 이 규칙과 달라 **"키보드 입력은 정차 중에만 할 수 있어요 · 주행 중에는 버튼으로만 바꿀 수 있어요"**로 바꿨다.

## 선호 조건이 코스 추천에 반영되는 방식
`data/CarePreferences.kt`. 토글은 "그날만 바꾸는 홈 필터 칩"의 **기본 상태**를 정한다.

| 토글 | 서버로 가는 조건 | 반영 위치 |
|---|---|---|
| 수유실 있는 곳만 | `conditions.needs += nursing_room` | 홈 칩 '수유실'의 시작 상태 → 홈 추천 요청, 문장 요청(조건 바꾸기) |
| 유모차 진입 가능 | `conditions.needs += stroller` | 홈 칩 '유모차' → 위와 같음 |
| 반려견 동반 가능만 | `conditions.with_pet = true` | 홈 칩 '반려동물' → 위와 같음 |
| 비·눈 오면 실내 우선 | (요청 값 아님) | 날씨가 비·눈(곧 올 가능성 포함)이면 홈의 '실내' 칩을 자동으로 켜 `indoor_only = true`. 꺼 두면 자동으로 켜지지 않는다 |

- 홈 칩을 누르는 것은 그 요청에만 영향을 주고 설정 값은 바꾸지 않는다. 설정에서 토글을 바꾸면 칩이 새 기본값으로 돌아가고 추천을 다시 받는다.
- **서버는 `needs`를 '제외 조건'이 아니라 가점(+2)으로 쓴다**(`planner._rank_outings`). 그래서 '수유실 있는 곳만'은 수유실이 확인된 곳을 위로 올리지만, 조건에 맞는 곳이 없을 때 아무것도 안 주지는 않는다. `with_pet`은 반려견 동반 후보 목록으로 바꾸고, `indoor_only`는 실내가 아닌 후보를 뺀다. 서버는 바꾸지 않았다.
- 한 번도 만지지 않은 토글은 예전 홈 칩 기본 규칙을 따른다: 36개월 미만 아이가 있으면 수유실·유모차 켜짐, 반려견이 함께면 반려견 켜짐, 비·눈 실내는 켜짐. 만진 토글은 그 값을 그대로 둔다(`CarePreferences.resolve`).
- 단위 테스트: `CarePreferencesTest` (요청 JSON에 `needs`·`with_pet`이 실리는지, 칩과 설정의 관계, 날씨 규칙).

## 저장 위치
- 선호 조건 4개·낮잠 시간: 기기 SharedPreferences `settings`(`nursing_room_only`, `stroller_ok`, `indoor_on_rain`, `pet_only`, `nap_start`, `nap_end`). 서버로 보내지 않는다.
- 낮잠 시간은 앱에 따로 있던 값이 없어 새로 두었다. 서버 `Child.nap_times`(문장형 '10:30–12:00 · 15:00–16:00')와는 아직 연결하지 않았다 — 차 앱↔서버 가족 정보 동기화(#123)에서 `nap_times`를 대응시킬지 정해야 한다.
- 수유 간격: `FeedingStore`(`feeding`/`interval_minutes`)를 그대로 쓴다. 설정에서 바꾸면 케어 화면 칩·홈 수유 카드도 같은 값을 본다.

## 데이터 전체 삭제
확인 대화상자 → (로그인 중이면) 서버 데이터도 지울지 한 번 더 → 실행.
- **이 차**: 가족 정보, 방문 기록, 저장한 코스, 수유 기록(마지막 수유·간격), 선호 조건, 낮잠 시간을 지운다. 로그인 정보는 그대로 둔다.
- **서버(로그인 중에만 선택)**: 서버 계약(`docs/research/web-server-contract.md` 7-4)의 삭제 API를 차례로 부른다 — `DELETE /me/visits`(방문 기록 전체), `DELETE /me/children/{id}`(아이와 그 수유 기록), `DELETE /me/members/{id}`. 계정과 공조 프리셋은 남긴다. 서버 삭제가 실패하면 기기 데이터는 지우지 않고 이유를 알려 준다(`data/ServerErase.kt`, `ServerEraseTest`).
- '이 차만 지우기'를 고르면 서버에 남은 데이터를 다음 동기화 때 다시 받을 수 있다고 화면에 적었다.

## Figma와 달라진 곳 (디자이너 확인 대상)
1. 안내 줄 문구(위 '주행 중').
2. 데이터 카드 문구 — Figma는 '생년월일·방문 기록 / 차 안에만 저장', '서버 전송 / "3세 이하 있음" 같은 요약만'이지만, 방문 기록 서버 저장·정확한 나이 전송 결정에 맞춰 `web-server-contract.md` 7절 문구를 가져왔다. 로그인 여부에 따라 첫 줄이 '차 안에만 저장' / '차 안 + 내 계정(서버)에 저장'으로 바뀐다.
3. 가족 프로필 카드에 '가족 정보 수정'/'가족 등록' 버튼, 낮잠 시간 행에 '›'(누르면 조절 창)를 더했다 — 실제로 고칠 수 있어야 해서.
4. 반려동물 값은 앱에 '소형견 1마리' 같은 정보가 없어 '반려견 함께 / 함께 가지 않아요'로 쓴다.
