## 1. 바로 연동한 것 (가입 없음)

### TourAPI 행사 정보 (`KorService2/searchFestival2`)
- 개선: 오늘 열리는 축제를 후보에 넣고 가점 → "축제가 있으면 위에 뜬다" (#48). 반경은 좌표로 직접 계산.
- 키: 기존 `DATA_GO_KR_KEY`로 실제 호출해 응답 확인함 (목록, 좌표, 시작일·종료일 포함).
- 한도: 개발계정 TourAPI 하루 1,000건 (#33 기존 내용). 전국 목록을 한 번(최대 500건)만 받아 6시간 저장해 호출 부담 없음.
- 품질 처리: 120일 넘게 이어지는 상설 행사 제외, 주류·성인·야간(나이트·야행·별빛 등) 행사 제외. API가 행사 시각을 주지 않아 야간 행사는 이름으로 거른다 (한계).
- 중복: 기존 관광지/문화시설과 겹치지 않음 (contentTypeId 15 행사).

### TourAPI 레포츠 (`locationBasedList2`, `contentTypeId=28`)
- 개선: 아이와 갈 만한 스케이트장(A03021300, A03020400), 눈썰매장(A03021200), 물놀이·수영장(A03030700), 복합 레포츠(A03050100)를 후보에 추가. 사격장·낚시·골프 등 제외.
- 반경 20km 호출에서 사격장(슈터스클럽)도 섞여 나오는 것을 확인해 세부 분류 허용 목록으로만 통과시킴.

## 2. 가입·신청이 필요해 연동하지 않은 것

> 가입·결제·약관 동의는 사용자가 직접 해야 합니다. 아래는 필요한 키 이름과 신청 위치입니다.

### 공공데이터포털(data.go.kr) 활용신청 계열
공통: 같은 `DATA_GO_KR_KEY` 하나로 쓰되, **데이터셋마다 "활용신청"을 따로** 눌러 승인을 받아야 합니다 (TourAPI도 같은 방식). 신청 위치: data.go.kr 데이터 페이지 → 활용신청. 개발계정은 보통 승인이 자동이고 트래픽은 데이터셋마다 다릅니다.

| 데이터 | 개선 | 확인된 것 | 확인 필요 |
|---|---|---|---|
| 한국문화정보원 한눈에보는문화정보조회서비스 (문화포털, 공연·전시) | 전시·공연 후보 | REST, `apis.data.go.kr/B553457/nopenapi/rest/publicperformancedisplays/period`·`/area`, 기간·지역·좌표·키워드 파라미터, 활용신청과 인증키 필요 ([문화포털 가이드](https://www.culture.go.kr/industry/apiGuideA.do)) | 일일 트래픽, 응답 필드(좌표·연령 등) |

| 전국모유수유시설 표준데이터 | 수유실 정확도 | 포털 검색에서 전국 단위 OpenAPI 페이지를 찾지 못함. 부산시 수유시설 API는 있음(경위도·무료) ([부산 데이터](https://data.go.kr/data/15034033/openapi.do)), 서울교통공사·국가철도공단 역사 수유실 API도 있음 | 전국 표준데이터가 파일(CSV)인지 API인지 |

| 전국주차장정보 표준데이터 | 주차 정확도 | 이번 조사에서 확인 못함 | 전부 |

판단: 문화포털 공연·전시와 놀이시설 정보가 후보 확장에 가장 유망합니다. 둘 다 활용신청 후 응답 필드를 확인한 다음 연동을 결정하세요. 표준데이터는 대부분 파일 형태여서, 쓴다면 서버에 미리 적재(#33)하는 방식이 맞습니다.

### 기상청 단기예보
- 서버에 이미 기상청 API허브 초단기실황이 있습니다(`app/weather.py`, PR #76, 키 `KMA_API_HUB_KEY`)에 초단기실황·초단기예보가 있어 비·눈이면 실내 우선 판단에 충분합니다. 반나절 이상 뒤 예보(단기예보)가 필요해지면 같은 허브 키로 추가할 수 있습니다(신규 가입 없음, 호출 한도 **확인 필요**).

### Google Places API (New)
- 확인됨: 장소 상세에 `regularOpeningHours`(영업시간), `goodForChildren`(아이 동반) 같은 필드가 있고, 모두 유료 SKU(Enterprise 계열)이며 필드 마스크를 지정해야 응답이 옴 ([필드 문서](https://developers.google.com/maps/documentation/places/web-service/data-fields)).
- 키: 구글 클라우드 계정 + 결제 수단 + API 키 필요. 키 이름 제안 `GOOGLE_PLACES_API_KEY`.
- 판단: 영업시간·아이 동반 정확도는 가장 좋지만 결제가 필요하고 사용량 과금이라 시연 이후(운영 단계) 검토. 호출 수를 줄이려면 "최종 선택된 1~3곳만 상세 조회"로 쓰는 방식이 맞습니다. 한국에서 구글 지도 데이터의 정확도(특히 국내 소규모 매장)는 **확인 필요**.

### 네이버 지역검색
- 네이버 개발자센터/API HUB에 앱을 등록해 Client ID·Secret을 받아야 합니다(키 이름 제안 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`). 지역검색은 결과 수가 적고(5건 안팎으로 알고 있으나 **확인 필요**) 카카오 로컬과 기능이 겹쳐서, 후보 풀 확장 효과가 작다고 판단합니다. 보류.

### 후보 풀에 넣은 방식
- **놀이터 있는 공원** (`scripts/load_public_data.py` → `server/data/playgrounds.json`): 85,400건 중 공공 도시공원·자연휴양림의 운영 중인 시설만 남기고 250m 안은 한 곳으로 묶어 **9,628곳**. 그중 나들이 장소다운 곳(놀이시설 3개 이상 묶인 큰 공원, 근린·호수·수목원·휴양림 등 이름)만 가까운 10곳까지 후보로. 동네 소공원 수천 곳이 후보를 덮지 않게 한 것. 편의 `kids_zone`=있음.
- **박물관·미술관·도서관** (`culture_facilities.json`, **2,279곳**): 가까운 10곳까지. 대학·연구소 소속 제외, 도서관은 목적지로 약해 -0.5.
- **오늘 열리는 전시·공연**(실시간, 6시간 저장): 이름·장소에 어린이·가족·체험·과학 같은 말이 있는 것만(성인·주류 제외). 기간 표시. 같은 이름은 TourAPI·카카오 후보와 한 번만.
- 이 소스들이 실패하거나 데이터 파일이 없어도 코스는 기존 후보로 나옵니다(경고 로그만).
- 데이터는 한 달에 한 번쯤 `cd server && .venv/bin/python -m scripts.load_public_data`로 다시 받으면 됩니다(문화시설 약 4분).

### 단기예보 보강
기존 `/weather`는 실황(비 오는지)과 초단기예보(하늘 상태)만 있어 "30분 뒤 비"는 알 수 없었습니다. 단기예보로 앞으로 6시간 최대 강수확률(`rain_chance`)과 곧 비 가능성(`rain_later`, 강수확률 60% 이상이거나 비·눈 예보)을 추가했고, 앱 홈은 `rain_later`일 때도 실내 칩을 먼저 켭니다. 예보 조회가 실패해도 실황은 그대로 나옵니다.
