## 1. 어떤 프레임이 기준인가

수진 페이지에는 MOBILE 디자인이 세 겹으로 쌓여 있다.

| 구역 | 내용 | 지금 기준인가 |
|---|---|---|
| **가장 최신_11/8일 웹앱 ver** (MOBILE · 09) | 360×800 웹앱(PWA), 탭 4개(홈·케어·그로우·MY), 화면 21개(차 QR 포함). "차량 원격 제어 없음 — 미리 세팅해 두면 다음 탑승 때 차 안 앱이 적용" | **예. 이 문서의 기준** |
| 1차안 › MOBILE · 08 심플 버전 | 탭 3개·화면 9개. ④ 케어 프리셋 3개(`지금 적용`, `탑승 전 최대 10분`, `일정 출발 10분 전 자동 적용`), ⑥ 경험맵 등 | 예전 안. 원격 적용이 들어 있어 정책(시동 꺼지면 앱 동작 안 함)과 맞지 않음 |
| 1차안 › MOBILE · 00~07 (확장 버전) | M01 홈·M10 캘린더·M23 원격 적용 시트 등 | 09가 이 둘을 합쳐 정리함 |

MOBILE 09에서 원격 적용(`지금 적용`, `출발 10분 전 자동 적용`)은 이미 빠졌다. 하단에 "원격으로 미리 켜기는 안전상 지원하지 않아요. 여기서 세팅해 두면 다음 탑승 때 차 안 앱이 적용해요"라고 적혀 있어 PR #65 중간안과 같은 방향이다. 그래서 **프리셋 관련해서 디자인과 현재 구현이 어긋나는 부분은 거의 없다.**

## 2. 화면 목록과 이동 흐름 (MOBILE 09)

```
① 시작     W00 차 화면 QR → S01 시작 → S01-1 이메일 가입 → S02 아이 정보 → S02-1 케어 정보 → S03 차 연결 → (S04 캘린더, 선택) → H01 홈
② 홈       H01 홈(일정 있음) → H02 일정 상세 → 「차에 보내두기」/「캘린더에 코스 저장」
           H01-1 홈(일정 없음) → H03 추천 코스 받기 → H04 코스 상세 → H05 일정 만들기 → H02
③ 케어     C01 케어 → C02 수유 기록 시트 → (수유 시각이 차 앱에 동기화)
                      → C03 프리셋 편집 → (다음 탑승 때 적용)
④ 그로우   (방문 푸시) → G03 방문 확인 시트 → G01 경험맵 → G02 노드·장소 시트 → 「다시 가기」→ H05
⑤ MY       M01 MY → M01-1 케어 정보 편집 → 「차량 연결 관리(QR)」
```

하단 탭: 홈 · 케어 · 그로우 · MY (네 화면 모두 공통).

### 디자인 시스템 (H01에서 읽은 값)
- 글꼴 Pretendard (400/500/600/700, 11~22px). **외부 CDN 없이** 시스템 글꼴 스택(`Pretendard`, `Apple SD Gothic Neo`, `Noto Sans KR`)으로 대체한다.
- 색: 글자 `#20252b`, 보조 글자 `#68727d`, 주색(진한 남색) `#263746`, 연한 파랑 칩 `#dce8ef`, 회색 면 `#f3f5f7`, 아이콘 자리 `#d5dbe1`, 테두리 `#c6cdd4`, 경고 빨강 `#e5484d`, 흰색 카드.
- 모서리 반경 6·8·10·12·16, 알약 모양은 999. 카드 테두리 1.5px.
- 버튼: 진한 남색 채움(주) / 흰 바탕+회색 테두리(보조), 높이 44px 이상.

### 화면별 구성요소
**H01 홈 · 일정 있음 / H01-1 일정 없음**
- 인사("지은 님, 좋은 아침이에요"), 주간 띠(일~토 + 날짜, 일정 있는 날은 점)
- 일정 카드: D-day, 출발 시각, 제목, 경유지·시간, 외출 멤버 동그라미, 칩(케어 예약·구글 캘린더), 「일정 상세 보기」
- 수유 한 줄(마지막 수유·다음 수유·남은 시간) + 「기록」
- 다음 탑승 때 적용: 프리셋 카드(탑승 준비 24℃·약풍·음량 낮게, 「자동」)
- 「어제 다녀온 곳 1곳 확인하기」(방문 확인 → G03)
- 다시 가볼까요?(과거 방문 장소 카드, 「코스로 만들기」「기록 보기」)
- 그다음 일정 + 「+ 일정 추가」
- 일정 없을 때(H01-1): 「이번 주 외출 일정이 없어요」 + 「추천 코스 받기」 「직접 일정 만들기」 + 오늘의 추천 코스 3개(날씨·수유까지 남은 시간·멤버)

**H02 일정 상세**: 캘린더 장소·시간, 이번 외출 멤버(변경), 도착·수유·여유 요약, 코스 타임라인, 케어 예약(탑승 준비 프리셋), 「차에 보내두기」 「캘린더에 코스 저장」
**H03 추천 코스 받기**: 언제(오늘·이번 주말·날짜), 누구랑, 꼭 필요한 것 칩(수유실·정차 공간·유모차 길·실내), 반경(5·10·20km), 코스 3개 카드(「일정으로」)
**H04 코스 상세**: 지도, 3곳·소요·지금 N대 가는 중, 타임라인, 케어 장소 요약, 「이 코스로 일정 만들기」 「경유지 순서 바꾸기」
**H05 일정 만들기**: 제목, 날짜·출발 시각, 장소·코스, 외출 멤버, 케어 예약 토글, 구글 캘린더에도 저장, 메모, 「저장」
**C01 케어**: 수유 타이머 카드(다음 수유·마지막·남은 시간·진행 막대·「지금 수유했어요」「시간 선택」), 모드 기본값(베이비케어·수면) 토글, 프리셋 3개 목록(탑승 준비·낮잠·수유 정차), 안전상 원격 미지원 안내, 자주 가는 케어 장소(수유실·정차 공간)
**C02 수유 기록 시트**: 지금/시간 선택, 종류(분유·모유·이유식), 양, 오늘 기록 목록, 「저장 · 다음 수유 HH:MM」
**C03 프리셋 편집**: 온도(−/+ 24.0℃, 아이 더위·추위로 권장값 안내), 풍량(미풍·약풍·중풍), 음량(최소·낮게·그대로), 언제 적용할까요(탑승하면 바로 / 일정 출발 시각에 맞춰 / 직접 실행만), 원격 미지원 안내, 「저장」
**G01 경험맵**: 이번 달 새 가지·잎 요약, 테마·키워드·장소 관계 그래프, 다음 스텝 카드(「일정에 추가」), 인사이트
**G02 노드·장소 시트**: 테마 방문 횟수·장소 수·키워드·장소별 최근 방문·아이 음성, 「다시 가기」
**G03 방문 확인 시트**: 「어제 서울숲에 다녀왔나요?」 방문했어요/아니요, 아이 기분 4가지, 귀갓길 음성, 사진 추가, 「저장 → 경험맵에 추가」
**M01 MY**: 아이 카드(이름·월령·수유 방식·간격·낮잠) + 「케어 정보 편집」「+ 아이 추가」, 기본 외출 멤버, 차량(연결됨·마지막 동기화) + 「QR로 다른 차 연결」, 캘린더 연결, 알림 토글 2개, 계정(이메일·「로그아웃」), 「데이터 전체 삭제」
**M01-1 케어 정보 편집**: 수유 방식·간격·낮잠(★ 필수 3), 카시트, 더위·추위, 멀미, 소리, 유모차, 알레르기·식이 제한
**시작 구간(S01~S04, W00)**: QR 랜딩 → 가입(이메일) → 아이 정보 2단계 → 차 연결 → 캘린더 연결

## 3. 서버에 있는 데이터 (`server/app/models.py` 확인)

| 테이블 | 내용 |
|---|---|
| `users` | 아이디(`login_id`), 비밀번호 해시, 표시 이름(`display_name`), 가입 시각 |
| `sessions` | 로그인 세션. `kind`=web/car, 기기 이름, 마지막 사용 시각, 폐기 시각 → **연결된 차 목록으로 쓸 수 있음** |
| `car_login_requests` | 차 QR 로그인 요청 |
| `climate_presets` | 사용자당 프리셋 **1개**(`ClimateSettings`: 온도·풍량·공조·에어컨·공기청정·열선 3종) + 보낸 시각·차 적용 시각 |
| `course_starts` | 코스 시작 집계(개인 식별 없음) |
| `parking_lots` | 공공 주차장 |

없는 것: 아이·가족 정보(이름·태어난 달·성향·케어 정보), 외출 멤버, 일정·캘린더, 수유 기록, 방문 기록·경험맵, 알림 설정, 프리셋 3개 구분·음량·적용 시점. 아이 나이는 앱이 추천 요청에 실어 보낼 뿐 서버에 저장하지 않고, 방문 요약도 요청에만 실린다(PR #55·#90).
서버 API로 이미 있는 것: `POST /course/suggest`(추천 3개, 출발 좌표 필요), `GET /weather`, `GET /care/nearby`, `GET /course/going`.

## 5. 정책·디자인과 다른 점 (화면에는 실제 동작만 쓴다)

1. **원격 적용 문구 없음**: MOBILE 08의 「지금 적용」「출발 10분 전 자동 적용」은 쓰지 않는다. 화면 문구는 「차로 보내기 → 시동 후 차 앱을 켜면 운전자가 '차에 적용'」 (PR #65 중간안). 디자인 09의 「탑승하면 바로 적용」도 현재는 "탑승 감지 자동 적용"이 아니라 "시동 후 차 앱이 받아서 확인하고 적용"이라 같은 문구를 쓰지 않는다.
2. **방문·경험맵**: 서버에 방문 기록이 없으므로 그로우 탭은 "방문 기록은 차 안 기기에만 저장돼요"를 알리는 정직한 안내 화면으로 만든다(사용자가 서버 저장을 허용하면 그때 G01~G03 구현).
3. **계정**: 디자인 이메일 → 구현 아이디. 가입 흐름은 바꾸지 않는다.
4. **원본 디자인의 목업 값**(지은 님, 서아 14개월, 아이오닉 5 등)은 화면에 고정 문구로 넣지 않는다. 데이터가 없으면 빈 상태 문구를 쓴다.

## 6. 구현 순서 (제안)

**1단계 — 추가 수집 없이 지금 가능 (이번 PR)**
1. 디자인 시스템(`base.html`, `static/m.css`) + 하단 탭바
2. 홈(H01-1 기반 + 실제 값 카드)
3. 케어 탭: 프리셋 1개 편집(C03 구성)과 보낸 상태, 원격 미지원 안내, 정직한 빈 상태
4. 그로우 탭: 방문 기록 정책 안내
5. MY: 계정, 연결된 차(해제), 차 연결 안내, 계정·서버 데이터 삭제
6. 로그인·가입·차 로그인 승인·프리셋 화면을 같은 디자인으로 맞춤

**2단계 — 사용자 결정 후**
- 아이·가족 정보 저장(S02·S02-1·M01·M01-1) → 홈 인사·월령, C03 권장 온도
- 수유 기록(C01·C02)
- 추천 코스 보기(H03·H04, `/course/suggest` 재사용) → 일정 저장(H02·H05) → 「차에 보내두기」
- 경험맵(G01~G03) — 방문 기록 서버 저장 정책 변경이 전제
- 프리셋 3개와 음량, 적용 시점

디자인과 달라진 점
- 디자인은 라이트 모드만 있어서 기존의 다크 모드 색을 없앴다.

- 「데이터 전체 삭제」는 서버에 있는 것만 지우는 「계정 삭제」로 바꿨다.
- 프리셋 풍량은 서버 값(1~8단)에 맞춰 8칸으로 두었다(디자인은 미풍·약풍·중풍 3칸).

## 8. 사용자 결정이 필요한 것

1. 아이·가족 정보(애칭, 태어난 달, 수유 방식·간격·낮잠, 외출 멤버)를 서버에 저장할지

## 10. 2단계 B 구현 결과 (이슈 #110)

| 경로 | 화면 | 디자인 | 실제 값 |
|---|---|---|---|
| `/m/grow` | 경험맵 | G01 | 이번 달 +N·새 가지, 가지(분야)별 장소 칩, 아직 없는 가지, 확인 대기 방문 안내 |
| `/m/grow/theme/{분야}` | 분야·장소 시트 | G02 | 방문 횟수·장소별 최근 방문·아이 기분 |
| `/m/grow/visit/{id}` | 방문 확인 | G03 | 방문했어요/아니요 + 아이 기분 4가지 → 경험맵에 추가 |
| `/m/course` | 추천 코스 받기·상세 | H03·H04 | 아이 월령·외출 멤버·확정된 방문을 조건에 반영해 `/course/suggest` 로직으로 3개 추천. 코스 카드를 펼치면 타임라인(H04) |
| `/m/` | 홈 | H01 | 어제 다녀온 곳 확인하기, 다시 가볼까요?(2주 넘게 안 간 단골 장소), 추천 코스 받기 |

디자인과 다른 점
- 경험맵은 관계 그래프 대신 **가지(분야) 카드 목록**이다. 디자인의 키워드 태그(#나비 등)와 아이 음성은 방문 기록에 음성·키워드를 받지 않기로 해서 제외.
- 「일정으로」「이 코스로 일정 만들기」「경유지 순서 바꾸기」「차에 보내두기」는 일정 저장을 이번에 하지 않기로 해서 만들지 않았다. 코스는 보기만 한다.
- 코스 추천은 현재 위치(브라우저 위치 권한)가 필요하다. 위치는 저장하지 않고 요청에만 쓴다. 지도·「지금 N대 가는 중」은 제외.
- 조건: 반경(5·10·20km) 대신 서버 조건에 있는 편도 이동 시간(20·40·60분), 「언제 가요」·「누구랑」은 저장된 아이·외출 멤버로 대신.

검증 메모: 로컬에서 실제 추천 API를 불러 봤지만 외부 장소 API(TourAPI)가 읽기 시간 초과(약 10초)로 응답하지 않아, 기존 `POST /course/suggest`도 같은 502였다(웹 코드 문제 아님). 그래서 코스 결과 화면은 가짜 플래너를 쓰는 서버 테스트로 확인했고, 화면에는 "외부 장소 정보를 불러오지 못했어요" 안내가 나오는 것까지 직접 봤다.
