## figma-watch 감시 범위를 페이지 전체로 넓히는 데 필요한 변경 (figma-watch 세션 몫, #157)
- 대상: 섹션 `351:2611` → 페이지 `130:5` 전체(`nodes?ids=130:5&geometry=omit`, Tier 1 1회는 그대로). 노드 약 27,700개(지금 8,293), `snapshot.json` 약 5MB 예상. 발표 슬라이드(`165:*` 30장, 959개)는 넣되 세션 알림은 보내지 않는다.
- 화면 단위: 페이지 최상위 FRAME + 모든 SECTION의 자식 FRAME/TEXT. 이름이 같은 화면이 두 섹션에 있으므로(피드백 섹션은 원본 복사본, H01은 피드백 섹션에만 2개) 화면 키를 `코드@섹션id`(예: `H01@369:11525`) 또는 노드 id로 둔다.
- 화면 코드 인식 추가: O01~O06·O04-1, S02·S02-1, G03, G01-B·G02-B(B안), Tile·Note.
- 화면 → 세션 표: G01·G03 → 1111-grow-jelly 실행 세션, C01~C12 → child-mode(진행 중)·1111-feeding-cleanup, H01·H02·H02-1·D01·Lib 셸 → 1111-shell-polish, O·S02 → 통제 세션. 실행 세션이 아직 없으면 통제 세션에만.
- 새 기준선: 이 세션이 받은 페이지 응답(버전 `2420237904099670604`, 기준선과 같은 버전)을 다시 쓰면 Tier 1 호출 없이 만들 수 있다. 파일은 이 세션 스크래치에만 있어 레포에 없다 → figma-watch 세션이 직접 받거나(1회), 같은 기계에서 경로로 읽는다.
- `state.json` Tier 1 카운터: 11월 8 → 12(감사 3 + 이번 1).
- `CHANGELOG.md`·`README.md` 머리말의 감시 대상 문구, `157-figma-watch.md` 결정("섹션 351:2611만 유지")을 사용자 새 요청(페이지 전체)으로 고친다. 테스트(`tools/tests/test_figma_watch.py`)에 두 섹션·같은 이름 화면 경우 추가.
