## 3. 파일 소유와 충돌 방지
- 위 표의 "주로 고치는 파일"은 그 세션만 고친다.
- 공유 파일(`MainActivity.kt`, `ui/TripViewModel.kt`, `ui/AppShell.kt`, `ui/Theme.kt`, `ui/Common.kt`, `ui/SitterGrid.kt`, `data/TripApi.kt`)은 **꼭 필요한 최소 추가만** 하고, 기존 줄은 바꾸지 않는다. 고치기 직전 `git fetch` 후 main을 합치고, 고친 뒤 바로 PR로 병합해 오래 들고 있지 않는다.
- 같은 파일을 다른 세션이 이미 고치고 있으면(열린 PR·브랜치로 확인) 먼저 통제 세션에 알리고 기다린다.
- 설정 화면, 경험 우주, 안내 화면(`guide/`, `ui/GuideScreen.kt`)은 건드리지 않는다.
- 케어 이전 시안 브랜치 `feature/139-care-hf03`는 병합하지 않는다. 그 로직(`FrequentCarePlaces`, 수유 타이머 상태, 지연 문구 함수와 테스트)만 `care-c01` 세션이 필요한 것을 가져온다.

## 5. 진행 방식 (모든 세션 공통)
1. 시작: `docs/HANDOFF.md`, 이 파일, 자기 지시 파일, `docs/design/pleos-1110/README.md`, 맡은 화면의 `02`·`04`·`05` 해당 부분을 읽고, `git log`·열린 PR·브랜치로 현재 상태를 확인한다.
2. 이슈 1개 → `feature/<번호>-<이름>` 브랜치 1개 → 작은 PR로 바로 병합(한국어 커밋·PR·이슈, 병합 제목 `PR #N 병합: <제목>`, 일부면 `Refs #N`, 푸시 전 `gh auth status`로 `HaeyeonYou` 확인). 한 PR은 화면 하나 또는 상태 한 묶음.
3. 의미 있는 단계마다 자기 지시 파일의 진행 로그를 갱신해 같은 브랜치에 커밋한다. 이 파일과 `HANDOFF.md`는 자기 작업 행만 고친다.
4. 검증: `cd android && ./gradlew :app:testDebugUnitTest`(순수 로직은 테스트를 같이 작성), 에뮬레이터 캡처를 Figma 화면(`docs/design/pleos-1110/assets/screens/*.png`)과 나란히 놓은 비교 이미지를 `docs/screenshots/`에 두고 PR에 첨부. 공유 에뮬레이터는 앱 ID 접미사(`-PappIdSuffix=.xxx`)로 분리하고 `adb`로 설치 시각·앞 화면을 확인한다. 실제 주행 전환·실차는 확인할 수 없으면 PR 본문에 그대로 적는다.
5. Figma 호출 한도(Education 플랜)가 소진돼 있을 수 있다. 저장된 이미지·문서를 기준으로 하고, 호출은 읽기 전용으로 꼭 필요할 때만 한다.
6. 시연용이 아니라 실제 데이터로 동작하고 다시 개발할 필요가 없게 만든다. 디자인에 없는 상태는 `05` 1절의 [제안]을 따르고, 따랐다고 PR에 적는다.

## 6. 토큰·사용량 한도 점검 (100% 전에 반드시 정리·커밋)
- 도구 `mcp__ccd_session_mgmt__get_usage`로 **5시간 한도, 주간 한도, 이 세션 컨텍스트 사용률**을 확인한다. 작업 시작 때, 이후 도구 호출 15번마다, 큰 빌드·에뮬레이터 작업 전에 확인한다. (이 도구가 없으면 통제 세션이 알려 주는 값을 따르고, 그래도 모르면 보수적으로 1시간마다 정리한다.)
- **5시간 한도 90% 이상, 주간 한도 95% 이상, 또는 컨텍스트 80% 이상이면** 새 작업을 시작하지 말고 즉시: ① 완성된 부분은 테스트 후 PR로 병합, ② 미완성 부분은 커밋해 `WIP` 브랜치로 푸시(병합하지 않음, 컴파일이 깨지는 상태로 main에 두지 않는다), ③ 자기 지시 파일의 상태·진행 로그·다음 단계·확인하지 못한 것을 갱신해 커밋, ④ 통제 세션에 "한도 근접으로 정리함 + 브랜치·PR·남은 일"을 보고하고 멈춘다.
- 컨텍스트 150K 근처면 위와 같이 기록을 먼저 커밋하고 사용자에게 `/compact`를 권한다(임의로 실행하지 않는다).
- 한도가 풀리면(5시간 한도는 창이 끝날 때) 지시 파일의 "다음 단계"부터 이어간다.
