# 작업 지시·기록: 방문 기록·경험 젤리 숫자를 화면마다 같게 (#234)

- 상태: **대기** · 세션명 `jelly-count` · 이슈: #234 · 1차 접수(11/15) 전 필수
- 공통 방식·파일 소유 규칙: [1110-screen-sessions-plan.md](1110-screen-sessions-plan.md)

## 1. 문제
마지막 통합 테스트(`1111-final-test-before-nas.md`)에서 코스를 내비 시뮬레이션으로 끝까지 진행했습니다(장소마다 머문 시간 10분 미만). 그 결과 같은 방문 기록의 숫자가 화면마다 달랐습니다.

| 화면 | 표시 |
|---|---|
| H04 코스 종료 | "경험 젤리 3개가 자랐어요" |
| 홈 젤리 타일 | "이번 달 1곳 · 1분야" |
| G01 그로우·G03 캘린더 | "0곳" |

- 저장 상태: 앱 방문 3건, 서버 1건(고산근린공원)
- 캡처: `docs/screenshots/final-1111/24-h04-end.png`, `25-g01-grow.png`, `26-g03-calendar.png`

## 2. 완료 조건
- H04, 홈 타일, G01, G03(그리고 음성 "젤리" 응답, 폰 웹 그로우)이 **같은 규칙·같은 출처**로 같은 숫자를 보여 준다. 규칙은 `grow/JellyModel.kt`(10분 이상 머문 방문 = 경험 1개) 하나만 쓴다.
- H04 문구는 실제로 생긴 젤리 수로 바꾼다. 0개면 0개에 맞는 문구를 쓴다(예: "10분 이상 머문 곳이 젤리가 돼요"). 지어낸 숫자는 쓰지 않는다.
- 앱 방문 3건과 서버 1건이 어긋나는 원인(방문 업로드 조건·실패·중복 제거 등)을 찾아 맞춘다. 서버를 고치면 서버 테스트도 통과해야 한다.
- 단위 테스트를 추가하고, 에뮬레이터 캡처를 남긴다(10분 미만 진행 1회, 가능하면 10분 이상 머문 경우 1회).
- 시연은 짧은 시뮬레이션으로 하기 때문에 그로우가 늘 비어 보이는 문제의 처리 방법을 PR에 적는다. 규칙을 바꿔야 하면 바꾸지 말고 사용자 결정으로 남긴다.

## 3. 범위
- 볼 곳: `grow/JellyModel.kt`, `grow/GrowJelly.kt`, `ui/GuideScreen.kt`(H04 문구), `ui/HomeScreen.kt`(젤리 타일), `ui/ExperienceScreen.kt`, `ui/ExperienceCalendar.kt`, 방문 기록 저장·업로드(`VisitStore` 등), 서버 방문 API.
- 공유 파일(MainActivity·TripViewModel·AppShell·Theme·Common)은 최소 추가만.
- 건드리지 않음: 코스 지도(`CourseMap*` — course-map-virtual 세션이 작업 중), 케어 화면.

## 4. 주의
- 에뮬레이터는 course-map-virtual 세션의 `.map` 앱과 같이 쓴다. 이 세션은 `-PappIdSuffix=.jelly` 같은 접미사 앱만 설치하고, 기본 앱이나 다른 세션 앱은 지우지 않는다. 화면을 가로채이면 잠시 뒤 다시 시도한다.
- 로컬 서버는 main 체크아웃에서 `--reload`로 :8000에 떠 있다. 서버를 고치면 PR 병합 뒤에 반영된다.
