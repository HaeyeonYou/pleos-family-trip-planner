# 작업 지시·기록: 좁은 창(분할 화면)용 배치

- 상태: **대기** · 세션명 `narrow-layout`
- 공통 방식·파일 소유 규칙: [1110-screen-sessions-plan.md](1110-screen-sessions-plan.md)

## 1. 목표와 완료 조건
사용자 결정(2026-11-12): "디자인이 없긴한데, 좁은화면용 배치 현재 디자인에서 찌그러지지 않게 알아서 맞춰줘"
- 지금 Pleos 분할 화면(⋮ 막대를 끌어 두 칸)에 들어가면, 앱이 1256×886 3열 캔버스를 통째로 줄여서 글자가 아주 작아진다(`docs/research/pleos-sdk.md`의 분할 화면 시험 결과 참고).
- 창 폭이 좁으면(기준값은 상수 하나로) 3열을 1~2열로 바꿔 쌓는다. 글자·터치 크기는 디자인 토큰 크기를 유지한다. 넘치는 내용은 세로 스크롤한다.
- 대상: 홈 H01, 코스 상세 H02(·H02-1), 코스 진행 H03·H04, 케어, 그로우, 주행 중 D01, 설정. 각 화면에서 열의 우선순위(무엇을 위에 둘지)는 Figma 3열 순서를 따르고, 주행 중에는 주요 행동 버튼이 첫 화면에 보이게 한다.
- 넓은 창(전체 화면)의 모양은 지금과 똑같아야 한다(회귀 금지).
- 완료 조건: 단위 테스트(폭 → 열 수 결정), 에뮬레이터에서 분할 화면 좁은 칸과 전체 화면 캡처를 화면별로 남긴다(`docs/screenshots/`).

## 2. 범위
- 고칠 곳: `ui/SitterGrid.kt`(SitterCanvas)과 각 화면의 열 배치부. 공유 파일(MainActivity·TripViewModel·AppShell·Theme·Common)은 최소 추가만 한다.
- 동시에 도는 세션: `jelly-count`(그로우·홈 타일 숫자), 이후 Figma 반영 세션(H02-1·H02-2·H03). 같은 파일을 고치면 충돌하므로, 열 배치 외의 내용은 건드리지 말고 main을 자주 받아 맞춘다.

## 3. 주의
- 에뮬레이터는 여러 세션이 같이 쓴다. `-PappIdSuffix=.narrow` 같은 접미사 앱으로만 시험하고, 기본 앱이나 다른 세션 앱은 지우지 않는다.
- 분할 화면은 앱이 강제로 만들 수 없다. 사용자가 ⋮ 막대를 끌어야 생긴다. 에뮬레이터에서는 `adb shell input swipe`로 막대를 끌어 재현한다(시험 결과 문서 참고).
