# 작업 지시·기록: 좁은 창(분할 화면)용 배치

- 상태: **완료** · 세션명 `narrow-layout` · 이슈 #245 · 브랜치 `feature/245-narrow-layout`
- 공통 방식·파일 소유 규칙: [1110-screen-sessions-plan.md](1110-screen-sessions-plan.md)

## 1. 목표와 완료 조건
사용자 결정(2026-11-12): "디자인이 없긴한데, 좁은화면용 배치 현재 디자인에서 찌그러지지 않게 알아서 맞춰줘"
- 지금 Pleos 분할 화면(⋮ 막대를 끌어 두 칸)에 들어가면, 앱이 1256×886 3열 캔버스를 통째로 줄여서 글자가 아주 작아진다(`docs/research/pleos-sdk.md`의 분할 화면 시험 결과 참고).
- 창 폭이 좁으면(기준값은 상수 하나로) 3열을 1~2열로 바꿔 쌓는다. 글자·터치 크기는 디자인 토큰 크기를 유지한다. 넘치는 내용은 세로 스크롤한다.
- 대상: 홈 H01, 코스 상세 H02(·H02-1), 코스 진행 H03·H04, 케어, 그로우, 주행 중 D01, 설정. 각 화면에서 열의 우선순위(무엇을 위에 둘지)는 Figma 3열 순서를 따르고, 주행 중에는 주요 행동 버튼이 첫 화면에 보이게 한다.
- 넓은 창(전체 화면)의 모양은 지금과 똑같아야 한다(회귀 금지).
- 완료 조건: 단위 테스트(폭 → 열 수 결정), 에뮬레이터에서 분할 화면 좁은 칸과 전체 화면 캡처를 화면별로 남긴다(`docs/screenshots/`).

## 2. 범위
- 고칠 곳: `ui/SitterGrid.kt`(SitterCanvas)과 각 화면의 열 배치부. 공유 파일(MainActivity·TripViewModel·AppShell·Theme·Common)은 최소 추가만 한다.
- 동시에 도는 세션: `jelly-count`(그로우·홈 타일 숫자), 이후 Figma 반영 세션(H02-1·H02-2·H03). 같은 파일을 고치면 충돌하므로, 열 배치 외의 내용은 건드리지 말고 main을 자주 받아 맞춘다.

## 3. 주의
- 에뮬레이터는 여러 세션이 같이 쓴다. `-PappIdSuffix=.narrow` 같은 접미사 앱으로만 시험하고, 기본 앱이나 다른 세션 앱은 지우지 않는다.
- 분할 화면은 앱이 강제로 만들 수 없다. 사용자가 ⋮ 막대를 끌어야 생긴다. 에뮬레이터에서는 `adb shell input swipe`로 막대를 끌어 재현한다(시험 결과 문서 참고).

### 구현 요약 (결정)
- 기준값 하나: `SitterGrid.STACK_BELOW_W = 1100`. 캔버스를 **전체 화면과 같은 배율(창 높이 기준)** 로 그렸을 때 폭(Figma px)이 1100보다 작으면 쌓는다. 전체 화면은 폭이 1256이라 해당 없음 → 넓은 화면은 코드 경로가 예전과 같다.
- 열 수: 폭 ≥ 1100 → 3열(원래 캔버스), ≥ 848(392×2+16+여백) → 2열, 그 아래 → 1열. `SitterGrid.columnsFor`·`layoutFor`(순수 함수, `NarrowLayoutTest`).
- 배율: 쌓을 때도 전체 화면과 같은 높이 기준 배율이라 글자·터치 크기가 전체 화면과 같다. 열 하나(392+48)가 안 들어갈 만큼 좁을 때만 그만큼 줄인다. 에뮬레이터 분할 칸(약 840dp)은 배율 약 1.32, 캔버스 폭 약 624 → 1열.
- 쌓기: 머리(음성 입력줄·칩, 또는 제목 줄)는 위에 고정하고 본문만 세로 스크롤. 칸마다 전체 화면 때와 같은 높이(본문 694, 코스 진행 742)를 줘서 칸 안의 weight·안쪽 스크롤이 그대로 동작한다. 폭은 칸에 맞춰 늘어난다. 순서는 Figma 열 순서(1→2→3, 넓은 열→3열).
- 공통 도우미가 처리: `SitterThreeColumns`·`SitterWideAndColumn`(+`top`, `focusThird`, `thirdWrapsWhenStacked`)·`SitterVoiceBar`(검색바가 남은 폭 사용)·`ShortcutDock`(칸 폭). `LocalSitterColumns`/`sitterStacked()`로 화면이 읽는다.
- 화면별: 코스 상세·코스 진행 본문을 `SitterWideAndColumn`으로 바꿈(전체 화면 모양 동일). 장소를 눌러 대체 후보(H02-1)나 진행 중 후보 목록을 열면 그 칸으로 자동 스크롤. 코스 진행 도착(H03)의 선택 카드 3개는 좁으면 한 줄 카드로 세로로 쌓음. 코스 종료(H04) 3열은 좁으면 내용 높이만 써서 버튼이 바로 이어짐. 요약 태그 줄은 넘치면 옆으로 민다. D01은 좁으면 카드 폭을 캔버스에 맞춤(높이 660 그대로 → 큰 버튼 2개가 첫 화면).
- 음성 패널(VX01~04)도 이미 전체 폭 세로 스크롤이라 쌓기 모드로 켰다(통째 축소 안 함). 온보딩은 `stackOnNarrow = false`로 예전처럼 축소.
- 설정은 옛 1:1 dp 화면이고 이미 `isNarrowWindow()`로 1열이라 손대지 않았다(전체 화면과 같은 크기).
- 캡처: `docs/screenshots/narrow-245/` (`n-*` 분할 좁은 칸, `f-*` 전체 화면).

## 5. 확인하지 못한 것
- **D01(주행 중 음성 제안)을 에뮬레이터에서 띄우지 못했다.** Virtual Console 기어 변경이 `{"error":"emulator_inactive"}`로 막혀 주행 상태를 만들 수 없었다. 코드로는 카드 폭만 캔버스(약 576)에 맞추고 높이 660·버튼 위치는 그대로라 첫 화면(캔버스 높이 약 885)에 들어간다고 판단했다(추정).
- 2열 모드(창 폭이 캔버스 848~1100 사이)는 단위 테스트로만 확인했다. 에뮬레이터 분할은 칸 폭이 약 840dp라 1열만 나온다.
- 케어 유아기(12개월 초과) 화면, 케어 시트·토스트·아이 선택 드롭다운, 그로우 월별 달력(G03)은 좁은 칸 캡처를 하지 않았다(같은 도우미를 쓰므로 쌓이는 것은 같다).
- 그로우 젤리 궤도 그림은 넓은 열(800)을 칸 폭(약 576)에 맞춰 그려 안쪽 작은 이름표가 전체 화면보다 조금 작다.
- 케어 영아기 3열의 긴급 타일 2개는 고정 크기라 칸이 넓어져도 늘지 않는다(왼쪽 정렬).
