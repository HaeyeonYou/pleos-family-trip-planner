- 상태: ✅ 완료 (2026-11-11) · 이슈 #168 · 브랜치 `feature/168-preset-apply-at` · PR #200(서버), 앱 PR은 HANDOFF 행 참고

## 1. 목표와 완료 조건
사용자 결정(2026-11-11): C08 디자인 그대로 **적용 시점 셋 중 하나**를 고른다.
- `apply_at` = `boarding`(탑승하면 바로) / `departure`(출발 시각) / `manual`(직접 실행). 아이별 프리셋마다 저장, 서버·웹 편집·차 앱 C08이 같은 값.
- 출발 시각 = **차 앱에서 고른(시작할) 코스의 출발 시각**. 따로 시각 입력 화면은 없다. 코스가 없으면 자동으로 켜지 않고 C08에 "코스를 고르면 출발 시각에 켜져요".
- 탑승보다 출발 시각이 먼저면 차 앱이 켜져 있을 때만 켠다(원격 공조 없음).
- 실제 동작: boarding = 탑승 감지 때 켬, departure = 출발 시각에 켬(앱 실행 중), manual = 누를 때만.
- 슬롯 기본값은 예전 고정 문구에 맞춤: 탑승 준비 `boarding`("탑승 시"), 낮잠 `manual`("수면 모드와 함께"), 수유 정차 `manual`("정차 시").

## 3. 결정 (이 작업에서 정한 세부)
- 서버 값 결정 순서: 아이 값 → 가족 기본값 → 슬롯 기본값. `PUT /presets/{slot}` 본문의 `apply_at`은 선택이고 비우면 지금 값을 둔다(예전 차 앱 호환). `when` 문구는 기본값이면 예전 문구, 바꿨으면 고른 시점 이름.
- 앱은 `apply_at`을 `ClimateSettings.applyAt`에 함께 실어 편집 비교·저장 대기열이 한 묶음으로 다룬다(공조에는 쓰지 않음, null이면 보내지 않음).
- 탑승 = 앱이 켜진 때(D8). 켜진 뒤 2분 안에 모드 값을 받으면 '탑승하면 바로' 모드를 켠다. 그 안에 못 받으면(로그인 전 등) 이번 탑승에서는 켜지 않는다(주행 중 갑자기 켜지지 않게). 공조 제어가 안 되는 차면 조용히 건너뛴다.
- 출발 시각: 고른 코스(`TripUiState.course.departureAt`, 오늘 HH:MM)가 바뀔 때 예약하고, 이미 지난 시각은 켜지 않는다. 코스를 바꾸면 다시 예약.
- 켜는 방식: 베이비케어 슬롯 = 베이비케어 켜기, 낮잠 = 수면 모드 켜기, 수유 정차 = 수유 정차 모드 켜기(정차 중일 때만). 여럿이면 베이비케어 → 수면 → 수유 정차 순서(공조는 뒤의 것이 이김). 이미 켠 모드는 건드리지 않는다. 켠 뒤 케어 화면 안내 "탑승해서 베이비케어 모드를 켰어요" / "출발 시각이라 …를 켰어요".
