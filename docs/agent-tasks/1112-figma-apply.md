## 디자이너 확인 전 임시 결정 (통제 세션 제안, 사용자가 바꿀 수 있음)
1. H03 '장소 바꾸기' 목록은 Figma에 화장실 자리표시 글이 들어가 있다. 앱은 **서버 대체 후보(같은 역할의 장소)**를 이 목록 모양으로 보여 준다. 태그는 QP4대로 `유아의자`라고 쓴다.
2. C07 월령 배지는 수유 기준(QD1)과 같은 **12개월 경계** 상수를 쓴다. 12개월 이하는 `영아기`, 넘으면 `유아기`이다. Figma의 "14개월 = 영아기"는 따르지 않는다.
3. H03 새 판의 `여기서 코스 끝내기`는 지금처럼 글자 버튼으로 둔다.
4. H02-2의 "경험 나무" 문구는 앱 용어인 `경험 젤리`로 쓴다.
5. 주차 혼잡도(`여유·보통·혼잡`)와 "혼잡도는 실시간 정보예요"는 실시간 데이터가 없어 **표시하지 않는다**(Figma PNG에서도 보이지 않음).
6. ~~H02-2의 "장소마다 기본 60분"은 **화면 문구만 맞추지 않는다.** 머무는 시간 규칙을 바꾸는 일이라, 세션이 현재 규칙과 차이를 PR에 적고 사용자 결정으로 남긴다.~~ → **사용자 결정(2026-11-12): 장소마다 체류시간 기본 60분.** 식사·나들이·카페 모두 60분(만 2세 이하 나들이 90분 규칙도 없앰), 주유 10분·충전 30분은 그대로, 코스 상세 ±30분 조절은 그대로. H02-2 머리글에 `장소마다 기본 60분` 표시.

## A. 코스 상세 H02-2·H02-1 + 반경 5~50km (세션 `course-detail-1112`)
- H02-2: 요약 칩(`주차 N곳 · 대체 M곳` 등), 장소 행마다 **주차 줄(접힘)** → 펼치면 추천 주차장 1곳(요금·일 최대·도보 분·유모차 경사로 여부) + `다른 주차장 · 걷는 거리순` 라디오 목록. 고른 주차장은 그 장소의 **길안내 도착지**가 된다(내비 경유지·목적지에 주차장 좌표 사용). 이때 타임라인 머리글, 행 아이콘(✕ · ↑ · ↓), 오른쪽 패널 문구도 맞춘다.
- H02-1: 타임라인 행 모양과 주차 줄을 H02-2와 같게 맞춘다.
- 데이터: 서버 주차장 DB(공공 주차장 CSV, 장소·날짜별 저장)와 카카오 주차장 검색을 쓴다. 요금·일 최대·경사로 등 없는 값은 지어내지 않고 빼거나 "정보 없음"으로 쓴다. 서버 API가 필요하면 서버도 고친다(테스트는 캐시된 실제 응답).
- **반경 5~50km**: H01 반경 칩·드롭다운(`H01-2-home-radius.png`)과 설정의 최소·최대를 Figma와 같게 바꾼다(지금 5·10·20). 서버 최대 20km 제한도 50km로 바꾼다. **카카오 로컬 검색 반경은 최대 20km**라서, 20km를 넘을 때 후보를 어떻게 모을지(예: TourAPI 위치기반, 여러 중심점 검색) 정하고 PR에 적는다. 넓은 반경에서 응답 시간과 API 한도도 확인한다.
- 볼 파일: `ui/CourseOverview.kt`, `ui/CourseDetailLogic.kt`, `ui/HomeScreen.kt`(반경 칩), `HomeFilters`, 설정 화면, `server/app/course/`, `server/app/sources/`.

## 확인하지 못한 것
- (C) 배지 색은 Figma PNG에서 눈으로 맞췄다(Figma API 미사용). 에뮬레이터는 다른 세션과 화면을 나눈 좁은 칸에서만 봤다(전체 화면 배치는 보지 않음).
- (C) Figma 행 설명의 "멀미 조금"(도윤)은 앱에 데이터가 없어 넣지 않았다.
- (B) 실제 서버 후보에 `stroller`·`nursing_room`·`kids_chair` 값이 없어(판교 코스 후보는 `kids_zone`만) 에뮬레이터에서는 조건 태그가 보이지 않았다. 태그 표시는 단위 테스트로만 확인했다.
- (B) 목록의 거리·분은 직선거리 × 도로 계수 어림이다. 고른 뒤 `/course/schedule`이 실제 시간을 다시 계산한다.
- (B) [여기서 코스 끝내기]로 `cancelRoute`를 보냈고 내비도 요청을 받았지만(로그 `OnCancelRouteRequest`), 내비 안내 화면은 바로 끝나지 않아 손으로 [안내 종료]를 눌렀다. #226부터 있던 동작으로 보이며, 이번 변경 범위 밖이라 고치지 않았다.
- (B) [돌아가기]는 누른 직후 다른 세션 앱이 앞으로 와서 화면으로 확인하지 못했다(`onPicker(null)`만 부른다). 좁은 창(분할 화면)에서 목록이 어떻게 쌓이는지도 따로 찍지 않았다.
- (B) 시험 중 내비 목적지가 바뀌어, 그때 돌던 narrow-layout 세션의 '옥된장' 안내가 끊겼다(그 세션에 알림).
- (A) 고른 주차장으로 실제 내비 경로가 잡히는지는 에뮬레이터에서 안내를 시작해 보지 않았다(공유 에뮬레이터의 내비를 다른 세션이 쓰는 중). 좌표 선택은 단위 테스트로만 확인.
- (A) 유모차 경사로·혼잡도·"식사 시 2시간 무료" 같은 가게 제휴 요금은 데이터가 없어 표시하지 않는다. 카카오에서 온 주차장은 "요금 정보 없음".
- (A) 반경 값은 지금처럼 앱을 다시 켜면 10km로 돌아간다(저장하지 않음, 기존 동작). 설정 화면에는 반경 항목이 없어 홈 칩만 바꿨다.
- (A) 50km 코스의 TourAPI 호출: 저장본 없는 첫 요청에서 목록 약 27건(20km 이하 3건). 강남 기준 후보 수집 1.3초(캐시 없는 실제 호출). 하루 1,000건 한도에서 넓은 반경 첫 요청이 잦으면 부족할 수 있다(같은 출발지는 6시간 캐시).
