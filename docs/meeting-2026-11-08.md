# 중간 회의 자료 (2026-11-08)

「오늘, 어디 가지?」 — 어린 자녀가 있는 가족을 위한 Pleos Connect 차량 앱.
기준: main 최신(PR #101까지), 서버 테스트 145개 통과. 디자인 기준은 피그마 지수 페이지 **HF 01~06**.

## 3. 피그마 내용 중 구현이 불가능하거나 바꿔야 하는 것

| 피그마 | 이유 | 대안·현재 처리 |
|---|---|---|
| **PX 계열의 지도 위에 얹는 패널** (내비 지도 위에 우리 UI 겹치기) | Pleos에서 다른 앱 위에 그리는 권한(SYSTEM_ALERT_WINDOW)을 줄 방법이 없고 시스템 지도는 앱이 그릴 수 없음 | **HF 기준**으로 전체 크기 패널. 지도가 필요한 곳은 카카오맵을 코스 카드로, 길 안내는 화면 분할(내비를 옆에 세로로)과 알림으로 |
| **1920×1080 / 1920×720 프레임** | 에뮬레이터 앱 창은 실제 1682×1210dp(분할 841×1210dp) | 실제 창 크기로 구현, 좁은 창은 별도 배치 |
| **시동 걸기·차 꺼진 상태에서 원격 공조** (블루링크식) | Vehicle SDK에 시동 API가 없고 차가 꺼지면 제어 불가. Vehicle Data/Fleet API는 읽기 전용·EU 한정·플릿 사업자용 | **프리셋 전송 → 시동 후 앱을 켜면 확인·적용** 방식으로 구현 (#71에서 팀 확정 필요) |
| **Pleos 계정으로 로그인** | universal-access SDK는 앱 토큰만 제공(사용자 프로필·OIDC 없음) | 자체 회원가입 + **차 QR 로그인** |
| **차량 위치를 임의 지정하는 시연** | 내장 내비가 외부 GPS 주입을 무시 | 내비의 **주행 시뮬레이션**(설정 버튼 길게 누르기) 사용 |
| **Gleo 음성 호출·차량 음량·화면 테마 전체 전환** | 시스템 음성 호출과 차량 음량/전체 테마 제어는 앱 권한 밖일 가능성이 큼(조사 문서 `docs/research/pleos-voice.md`에서 확인 필요) | 앱 안 마이크 버튼, 앱 패널 안의 톤 전환과 앱 음성 안내 볼륨 |

| **아기 카메라 연동·확장 영역** | 차량 카메라/IoT 연동 SDK 확인 안 됨 | 이번 범위에서 제외 |
| **운전 중 키보드 입력** | 운전자 주의 분산 가이드 | 키보드 입력만 막고 버튼·음성 문장 버튼은 허용 |

## 4. 시연 방법

**사전 준비 (시연 전 10분)**
1. PostgreSQL 켜짐 확인: `brew services list`
2. 서버 실행(Mac): `cd server && .venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000 --no-access-log`
3. 에뮬레이터 `Pleos_Connect_v2.1.0` 부팅, 앱은 운전자(사용자 10)에 설치됨. 앱이 로그인 상태인지 확인(아니면 QR → 폰 로그인)
4. 홈에서 **"지금 수유했어요"를 한 번** 눌러 수유 시각을 현재로 맞춤
5. 폰은 Mac과 같은 Wi-Fi에 연결(QR 로그인·프리셋 전송 시연용)

**시연 순서 (약 5분)**
1. **홈**: 코스 3개와 정보 칩, 필터 칩을 켜고 끄면 추천이 바뀜, "다른 코스 보기"
2. **코스 상세**: 타임라인, 지도 경로, 주차 정보, 경유지 편집(교체)
3. **코스 시작** → 내비 → 설정(톱니) 버튼 **2초 이상 길게 눌러** "주행 시뮬레이션 → 시작" → 도착 이벤트 → 방문 기록
4. **케어**: 베이비케어 토글 → 상단 공조 표시가 바뀜, 수면 모드, 급한 케어 찾기
5. **음성**: 마이크 버튼 → "너무 더워" / "기저귀 갈 데 어디 있어?" (에뮬레이터는 소리 입력이 없어 문장 버튼·입력창 사용)
6. **그로우**: 경험 우주(방문 후 노드가 늘어남)
7. **폰**: 모바일 웹에서 공조 프리셋 전송 → 차 앱에서 확인·적용

**주의**: 앱 프로세스가 멈춰 있으면 내비 도착 이벤트를 놓침. 서버가 꺼져 있으면 추천이 비어 보임.

## 5. 예상 질문과 답 (QnA)

1. **Q. 어디까지 실제로 동작하나요?** A. 홈 추천, 코스 상세·지도, 길 안내와 도착 기록, 케어(실제 공조 제어), 음성 자연어, 그로우, 계정·프리셋이 에뮬레이터에서 동작합니다. 미구현은 HF06 지연 알림, 수유실 전용 데이터, NAS 배포입니다.
2. **Q. 추천은 매번 같은 결과 아닌가요?** A. 처음엔 점수가 거리에 쏠려 그랬습니다. 지금은 후보 풀 확장(공공데이터), 방문 이력 반영, 점수 다양화, "다른 코스 보기"로 순환합니다.
3. **Q. 사용자 문장은 어디로 가나요?** A. 서버가 Claude Haiku로 해석하고 키는 서버에만 있습니다. 로그에는 문장 원문을 남기지 않고, 실패하면 규칙 기반으로 되돌아갑니다. 제출물에 개인정보 안내 한 줄을 넣을 예정입니다.
4. **Q. 차 시동·공조를 밖에서 켤 수 있나요?** A. SDK에 시동 API가 없고 꺼진 차는 제어할 수 없습니다. 폰에서 프리셋을 보내 두면 시동 후 앱에서 확인·적용합니다.
5. **Q. 공조 제어는 실제 차량에서도 되나요?** A. 에뮬레이터에서는 속성별로 지원 구역을 확인해 적용하고 온도를 읽어 확인합니다. 지원하지 않는 차량은 안내만 하고 앱은 멈추지 않습니다.
6. **Q. Pleos 계정으로 로그인하나요?** A. SDK가 사용자 정보를 주지 않아 자체 회원가입과 QR 로그인입니다. 토큰은 해시로만 저장하고 90일 후 만료됩니다.
7. **Q. 운전 중에 조작해도 되나요?** A. 키보드 입력만 막고, 동승자가 버튼을 쓸 수 있습니다. 위험할 수 있는 음성 명령은 "응/아니야"로 되묻습니다.
8. **Q. 지도는 어떻게 보여주나요?** A. Pleos에는 지도 SDK가 없어 카카오맵 SDK로 경로를 그립니다. 길 안내는 내장 내비를 쓰고, 화면을 나누면 내비와 앱을 나란히 봅니다.
9. **Q. 인터넷이 끊기면요?** A. 지도는 간이 지도로, 음성은 규칙 기반으로 되돌아갑니다. 코스 자체를 보여 주는 오프라인 데모 모드(#21)는 아직 없습니다.
10. **Q. 장소 데이터가 정확한가요?** A. 관광공사, 카카오, 공공데이터를 합치고 야간 행사·주점은 제외합니다. 영업시간 등 정확도 한계가 있어 "정보 없음"과 "없음"을 구분해 표시하고, 수유실은 전용 API 승인을 기다리는 중입니다.
11. **Q. 서버는 어디에 두나요?** A. 지금은 로컬이고 확정되면 NAS(Docker, DDNS, HTTPS)로 옮깁니다. DB는 SQL 파일로 옮길 수 있게 문서화했습니다.
12. **Q. 아이 개인정보는요?** A. 생년월일은 기기에만 있고 서버에는 월령만 보냅니다. 방문 기록도 기기에 저장합니다.
13. **Q. 실차 확인은 했나요?** A. 아직 에뮬레이터만입니다. 마이크 음성 입력, 실제 시트·핸들 열선 동작은 실차에서만 확인할 수 있습니다.
14. **Q. 피그마와 다른 점은?** A. 지도 위 패널(PX)은 Pleos에서 불가능해 HF 기준으로 했고, 해상도도 실제 앱 창 크기에 맞췄습니다(3번 표).
15. **Q. 남은 일정은?** A. 오늘 중간 회의 후 HF06·설정·수유실·오프라인 모드, 이후 NAS 배포와 release APK·시연 영상(1차 제출 11/15) 순서입니다.

## 7. Haiku 5.5로 하는 일과 비용

**하는 일 (두 가지뿐, 모두 서버에서)**
1. **조건 입력 문장 해석**: "비 오는데 아기랑 실내에서 오래 있을 곳" 같은 자유 문장을 테마·실내 여부·관심사·소요 시간·필요 시설 조건(JSON)으로 바꿉니다.
2. **음성 명령 해석(`/voice/interpret`)**: 규칙으로 알아듣지 못한 문장을 정해진 동작 목록 중 하나와 인자로 바꿉니다(공조 조절, 수유 기록, 탭 이동, 코스 조건 변경, 케어 상황 등). 목록 밖의 동작은 거부하고, 위험할 수 있는 동작은 "응/아니야"로 되묻습니다.
- 두 호출 모두 3초(앱 쪽은 3.5초)를 넘기거나 실패하면 **규칙 기반으로 되돌아가** 앱이 멈추지 않습니다. 로그에는 문장 원문을 남기지 않습니다.

**Haiku가 하지 않는 것**: 장소 추천 자체(점수 계산은 서버 코드), 실시간 정보 답변(날씨·도착 시각은 앱이 가진 값으로만 답함), 차량 직접 제어(앱이 허용한 동작만 실행).

**가격**: Claude Haiku 5.5는 입력 **$0.10 / 1M 토큰**, 출력 **$0.50 / 1M 토큰** (프롬프트 100K 토큰 이하 기준, Anthropic 공식 가격표 캐시본 2026-10-06).

**한 건당 비용 추정** (정확한 토큰 수는 서버 로그에서 확인 가능, 아래는 어림값):
- 입력 약 1,000토큰(지시문 + 동작 목록 + 문장) × $0.10/1M = $0.0001
- 출력 약 100토큰 × $0.50/1M = $0.00005
- 합계 **약 $0.00015 (대략 0.2원)**. 1,000건을 호출해도 약 $0.15(200원 안팎)입니다.
- 시연·심사 기간처럼 하루 수십~수백 건이면 **하루 몇 십 원 수준**입니다. 프롬프트 캐싱을 쓰면 입력 단가가 더 내려갑니다.
- API 키는 서버 `.env`에만 있고, 사용량 한도는 Anthropic 콘솔에서 월 한도를 걸어 둘 수 있습니다.

## 8. API로 할 수 없는 것 (정보 한계)
- **영업시간·휴무·대기 시간**: 카카오 로컬과 관광공사에는 일반 상점의 실시간 영업 정보가 없습니다. 식사·카페 후보의 "지금 영업 중" 판단은 정확하지 않습니다.
- **수유실·기저귀 교환대의 전국 정밀 정보**: 전국 단위 공공 API가 없거나 승인 대기 중입니다(수유정보 알리미 키 신청 중). 쇼핑몰 안 층·위치 수준은 확신할 수 없어 "있음 / 정보 없음"으로 표시합니다.
- **키즈카페 상세(예약·연령 제한·가격)**: 공공데이터에 없고 카카오 검색으로 위치만 알 수 있습니다.
- **실시간 교통·정체 기반 지연 예측**: **가능하지만 미구현(#17)**. 내장 내비 SDK의 남은 시간(`DrivingInfo`)·정체 정보(`TrafficStatus`)와 카카오 길찾기(현재 교통 속도·상태 필드, 미래 시각 길찾기)를 쓸 수 있습니다. 내비의 남은 시간이 교통을 반영하는지는 에뮬레이터 로그로 확인이 필요하고, 카카오 소요 시간의 실시간성 여부와 상업 이용 제휴 조건은 확인이 더 필요합니다.
- **"지금 N대 가는 중"**: 외부에 없는 정보라 **우리 서버가 코스 시작을 집계**한 값입니다(이용자가 적으면 작은 수).
- **차량 쪽**: 시동 제어, 꺼진 차 원격 제어, Pleos 계정 정보, 내장 내비의 위치 임의 지정은 SDK가 지원하지 않습니다(3번 표).
